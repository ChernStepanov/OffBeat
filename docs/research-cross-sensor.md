# Амазония: пространственная связь L/C-band не означает согласия изменений

## Вывод

Новое офлайн-исследование сопоставило NISAR GCOV и OPERA RTC-S1 в тех же 1 024 точках Амазонии, проверив pairing дат, class confounding и связь уровней отдельно от связи изменений. На шести уникальных парах NISAR—Sentinel-1 абсолютные пространственные уровни HV/VH связаны умеренно (`r=0.462`, 6 144 point-date пары). После центрирования по WorldCover-классу **и дате** связь остаётся (`r=0.362`), то есть не объясняется только разницей лес/grassland и сдвигом датных медиан.

Контрпример: связь изменений существенно слабее в этой выборке. Корреляция последовательных изменений NISAR HV и OPERA VH на тех же точках `r=0.172` (5 120 point-interval записей, но только пять последовательных интервалов). Аналогично HH/VV: уровни `r=0.481`, внутри-класс/дата `r=0.355`, изменения `r=0.173`. Это описательное ограничение межсенсорного переноса, **не** доказательство физической причины, классификационной точности или преимущества частоты.

Для contrast `r(levels) − r(changes)` выполнен paired spatial block bootstrap: каждый replicate использует один набор блоков для обоих r, сохраняя все даты/интервалы каждой пространственной точки. HV/VH contrast равен **0.290**; 95% percentile CI положителен на всех масштабах: **2×2 cells [0.249, 0.324]**, **4×4 [0.239, 0.330]**, **8×8 [0.234, 0.323]** (1 000 повторов на масштаб). HH/VV contrast равен **0.308**, CI соответственно **[0.273, 0.338]**, **[0.261, 0.344]**, **[0.233, 0.363]**. Это пространственная неопределённость, условная на этой выборке, не p-value и не неопределённость по независимым датам/событиям.

Расстояние между точками выборки — примерно 87 м по сетке bbox; блоки имеют стороны около 174, 348 и 696 м. Интервалы чувствительны к масштабу spatial resampling и не описывают перенос на другие места. Pooled r имеет собственный CI в JSON; он не заменяет интервал contrast.

## Данные и точное сопоставление

Команда из корня репозитория:

```bash
/tmp/opencode/nasa-venv/bin/python scripts/research_cross_sensor.py
/tmp/opencode/nasa-venv/bin/python -m unittest scripts.test_research_cross_sensor -v
```

Входы и SHA-256 фиксируются в `data/research/cross-sensor.json`:

* `data/amazon.json`: шесть NISAR L2 GCOV PROVISIONAL дат `2026-07-18, 08-11, 08-23, 09-04, 09-16, 09-28`; track 146/frame 175, ascending, HH/HV. 1 024 точек, включая 575 WorldCover 2021 class 10 (tree cover) и 449 class 30 (grassland).
* `data/amazon/sentinel1.json`: OPERA RTC-S1, 86 дат, `2024-01-10`—`2026-11-02`, VV/VH, гамма-ноль dB. В provenance 219 успешно прочитанных гранул. C-band в сопоставленных гранулах — track label T170, descending (`S1D`), IW1/IW2; это чтение из ID гранул, не отдельный point-level источник каждого пикселя.
* `data/amazon-manifest.json`: NISAR catalogue metadata/IDs. Acquisition timestamps для всех шести дат — в `data/subsets/amazon-dense/<date>.json`; их hashes входят в результат. WorldCover — provenance в `data/amazon.json`; исходный subset `data/subsets/amazon/2026-07-18_2026-08-11/worldcover.npz`.

OPERA измерения не содержат координат и ID отдельным массивом. Скрипт assert-ит каждый NISAR ID `AMA rX cY` и lat/lon против ячейки центра сетки 32×32+bbox; затем проверяет `provenance.points_sha256` против SHA-256 упорядоченных координат. Это привязывает OPERA sample index к координатам согласно extraction contract в `scripts/opera_rtc.py`, но не является самостоятельным per-point spatial join или проверкой точности регистрации: NISAR берёт ближайшую native ячейку, OPERA — ближайшую 30-метровую RTC ячейку.

Основные пары: все шесть NISAR acquisitions сопоставились с отдельной OPERA датой на **−1 календарный день** (C-band раньше NISAR). NISAR start около 09:04 UTC, гранулы OPERA около 08:58 UTC предыдущего дня; каталожный UTC lag диапазон около **−24.100…−24.098 часа**. Это диапазон трёх burst-granule IDs на дату, не точный lag измерения каждого пикселя: неизвестно, какой burst заполнил конкретную точку. При tolerance 0 дней пар нет; при 3/6/12 днях — все те же шесть, без повторного использования OPERA acquisition. JSON даёт календарный lag, NISAR start UTC и все timestamps гранул на дату. Выбранные NISAR — track 146 ascending, OPERA IDs — T170 descending; это не одновременные проходы.

### Методы и абляции

1. **Допуск даты 0/3/6/12 суток:** уникальное назначение ближайшей C-band даты каждой NISAR дате. Результат устойчив между 3–12 днями, но все пары имеют один и тот же −1 день; тест 0 дней неприменим, а не отрицателен.
2. **Поляризации:** сравниваются cross-pol HV↔VH и co-pol HH↔VV отдельно. Эти каналы не объявляются физически эквивалентными.
3. **Уровни против изменений:** pooled spatial correlation по уровням противопоставлена корреляции разностей между последовательными matched acquisitions на каждой координате.
4. **Class/date centering:** вычитается медиана соответствующего WorldCover-класса на каждой дате отдельно у каждого сенсора. Pooled r уменьшается, но не меняет знак; сигнал частично связан с классовым/временным составом, однако не исчезает.
5. **Matching и валидность:** assert проверяет NISAR ID, lat/lon, grid cell-center, форму массива и ordered-coordinate hash. RTC не хранит отдельные ID/координаты, поэтому matching зависит от extraction order contract, а не независимого spatial join. Null не заполняется. В RTC JSON нет per-point source granule, geometry mask или quality mask: строгая geometry/quality абляция недоступна, finite value не означает quality-checked.
6. **Парная пространственная неопределённость contrast:** 1 000 bootstrap draws на размерах 2×2, 4×4, 8×8; один и тот же draw блоков используется для `r(levels)` и `r(changes)`, после чего берётся их разность. Все даты/интервалы точки сохраняются вместе. Приблизительные стороны блоков — 174/348/696 м; 64 блоков для 4×4. Не рассматриваются ни пиксели, ни даты как независимые реплики.
7. **Центрирование изменений по классу и интервалу:** дополнительно проверено, остаётся ли cross-sensor change association после вычитания медианы изменения соответствующего класса отдельно для каждого интервала. Для HV/VH `r` уменьшается с 0.172 до 0.065; для HH/VV — с 0.173 до 0.054. Это указывает, что часть слабой общей связи изменений относится к общему сдвигу класса/интервала; механизм не идентифицирован.
8. **Длинная C-band история:** 86 дат VH агрегированы в медианы даты отдельно по классам, затем по календарному месяцу. Наблюдаемый межмесячный диапазон медиан — 2.60 dB для grassland и 1.22 dB для tree cover. Это описательный сезонно-временной контекст: месяцы объединяют годы, поэтому он смешивает сезон, тренд и изменения геометрии/обработки и не является разложением сезонности.

Оптика для этого вопроса не добавляет независимую цель измерения: она не нужна для межсенсорного correlation-анализa. Никакие внешние слои в данном исследовании не скачивались.

## Что найдено и что не найдено

| Каналы | Pooled уровни | После class+date centering | Внутри класса (уровни) | Последовательные изменения |
|---|---:|---:|---|---:|
| NISAR HV / OPERA VH | 0.462 | 0.362 | grassland 0.323; tree cover 0.431 | 0.172 |
| NISAR HH / OPERA VV | 0.481 | 0.355 | grassland 0.290; tree cover 0.443 | 0.173 |

| Contrast `r(levels) − r(changes)` | Оценка | 2×2 block CI | 4×4 block CI | 8×8 block CI |
|---|---:|---:|---:|---:|
| HV/VH | 0.290 | [0.249, 0.324] | [0.239, 0.330] | [0.234, 0.323] |
| HH/VV | 0.308 | [0.273, 0.338] | [0.261, 0.344] | [0.233, 0.363] |

Коэффициенты — Pearson r описательных парных выборок. Изменения вычисляются как разность двух измерений одного point между последовательными matched dates, а затем коррелируются по paired differences; их нельзя подменять разностью медиан. Уровневая связь и ассоциация изменений отвечают на разные вопросы. Наблюдаемая разница между r уровней и r изменений — новый результат этого анализа; она опровергает простую трактовку «сходные spatial patterns означают согласованный change». Simpson reversal не найден: знак pooled-vs-centered сохраняется и внутри обоих классов.

Результаты — не причинное сравнение длины волны. Проверка extractor: NISAR — GCOV gamma0 HH/HV; `scripts/opera_rtc.py` читает OPERA RTC VV/VH assets и преобразует positive linear power через `10*log10`; sigma0 auxiliary не используется. Это не независимая проверка radiometric quality или mask. Частота спутника смешана с поляризацией, временем прохода, look geometry, posting/resolution, продуктом и обработкой. Нет независимых меток вырубки или иных событий; поэтому нет accuracy, recall, event attribution или оценки площади.

## Ограничения воспроизводимости / интерпретации

* Это одно малое окно, один трек NISAR, шесть NISAR acquisitions и пространственно зависимые точки. В 5 интервалах изменения 5 120 точечных записей не превращаются в 5 120 независимых временных повторов.
* NISAR ID и координаты валидируются совместно; RTC не содержит собственного per-point ID/coordinate, связь с порядком — через extraction contract и hash. Это не независимый spatial join.
* На каждую OPERA дату есть несколько bursts; per-point вклад, geometry/quality masks отсутствуют. Поэтому строгая geometry/quality ablation невозможна, измерения не называются quality-checked. `S1D/T170` — метаданные гранул, не доказательство одинаковой point geometry.
* UTC timestamps доступны по granule ID/sidecar, но не по конкретному измерению. Matching основан на календарных датах; UTC lag range — только для каталожных гранул.
* WorldCover 2021 — исторический класс; class 30 означает grassland, не обязательно пастбище.
* Нет смещённого географического отрицательного контроля: он здесь не нужен для основного paired association и мог бы создавать искусственное сравнение за пределами одного изучаемого окна. Зато есть spatial block bootstrap и within-class/date centering; ни то ни другое не заменяет независимые регионы/события.
* Synthetic data отсутствуют: скрипт использует только реальные измерительные JSON, NISAR catalogue manifest и sidecar receipts; тесты проверяют входы и правила matching.
